# 共用歌曲识别

歌单导入、歌词匹配和歌曲信息匹配共用 `src/domain/songIdentity.ts`。该模块只识别文本，不请求网络、不决定是否保存，也不修改来源资料或用户输入。

共用规则包括 HTML 实体与全角字符归一化、编号和展示标签清理、引号内歌名提取、相邻歌手识别、双语标题与合作歌手括号处理，以及现场、翻唱、伴奏、管弦、混音、变速、重制、语言等版本标记。英文曲名按词匹配，上传者名称不能作为歌手证据。多个引号歌名不自动截成第一首；歌名和歌手前后顺序不明时最多产生两个查询。

## 各功能保留的规则

| 功能 | 识别后的规则 |
| --- | --- |
| 歌单导入 | 保留标题／歌手／时长评分、版本冲突、短标题、详情确认和分 P 校验；父视频标题不能证明每个分 P 都是目标歌曲；UP 名称仅为弱证据。 |
| 自动歌词 | 只接受规范化后歌名和歌手一致、时长接近且有有效歌词的结果；不覆盖已有选择。 |
| 手动歌词 | 保留标题／歌手权重、来源轻微偏好、动态歌词和时长排序，由用户选择。 |
| 歌曲信息 | 保留标题／歌手权重、来源和封面偏好；用户选择结果并保存后才更新资料。 |

歌词和歌曲信息的查询编排在 `services/songLookup.ts`：单个明确查询只请求一次，歧义查询最多两次，按来源和条目 ID 去重。部分失败保留成功结果，全部失败保留原始错误；切换账号后不再查询另一个方向，也不返回过期结果。歌词的服务失败警告继续传递到选择界面。

手机、桌面和鸿蒙使用同一个服务入口；大屏歌词选择也直接使用该识别模块。平台原生层不维护第二套识别正则。新增规则先加入共用模块，功能专用的置信度、时长和保存策略留在各自用例中。

## 回归测试

`tests/song-recognition.test.mjs` 通过实际服务入口和 mock IPC 验证三个用途的长标题、实体、版本、查询次数、去重、失败与账号 ABA。原有 `lyric-query`、`automatic-lyrics`、`music-match-ranking`、`external-song-match` 和 `playlist-import` 测试保留各功能的接受与拒绝边界。执行 `npm test`、`npm run build` 和 `npm run build:large-screen`。
