# 共用歌曲识别

歌单导入、歌词匹配和歌曲信息匹配共用 `src/domain/songIdentity.ts`。该模块只识别文本，不请求网络、不决定是否保存，也不修改来源资料或用户输入。

共用规则包括 HTML 实体与全角字符归一化、编号和展示标签清理、引号内歌名提取、相邻歌手识别、双语标题与合作歌手括号处理，以及现场、翻唱、伴奏、管弦、混音、变速、重制、语言等版本标记。英文曲名按词匹配，上传者名称不能作为歌手证据。多个引号歌名不自动截成第一首；歌名和歌手前后顺序不明时最多产生两个查询。

## 各功能保留的规则

| 功能 | 识别后的规则 |
| --- | --- |
| 歌单自动匹配 | 来源和候选均经 `recognizeSong` 识别，以曲名、歌手、版本为主；时长连续评分，播放量对数封顶加分。按需验证实际 CID，直接保存一个合理结果。父 BV 标题不能证明每个分 P 都是目标歌曲；未知分 P 时长不能当作单曲时长。 |
| 手动更换视频 | 正常 B 站分页搜索，不经过原歌曲的匹配资格过滤；选择或试听时才获取详情，多 P 由用户明确选择。 |
| 自动歌词 | 只接受规范化后歌名和歌手一致、时长接近且有有效歌词的结果；动态歌词优先，时长误差与最佳结果相差不超过 3 秒时按 QQ 音乐 → 网易云 → 其他来源选择；不覆盖已有选择。 |
| 手动歌词 | 保留标题／歌手权重、来源轻微偏好、动态歌词和时长排序，由用户选择。 |
| 歌曲信息 | 保留标题／歌手权重、来源和封面偏好；用户选择结果并保存后才更新资料。 |

歌词和歌曲信息的查询编排在 `services/songLookup.ts`：单个明确查询只请求一次，歧义查询最多两次，按来源和条目 ID 去重。部分失败保留成功结果，全部失败保留原始错误；切换账号后不再查询另一个方向，也不返回过期结果。歌词的服务失败警告继续传递到选择界面。

手机、桌面和鸿蒙使用同一个服务入口；大屏歌词选择也直接使用该识别模块。平台原生层不维护第二套识别正则。新增规则先加入共用模块，功能专用的置信度、时长和保存策略留在各自用例中。

导入歌曲的“苏打绿版”等括号仅在与来源已知歌手相符时作为表演者标注处理，不能泛删所有“某某版”；Live、伴奏、翻唱、语言版本等要求保持独立。录音棚、私藏馆等长标题从明确歌名提取身份；合作歌手信息作为辅助证据。多引号串烧不自动截成第一首。

原歌曲资料属于稳定的导入条目，不改变播放器的 BVID＋CID 身份。更换视频、补全和各端界面使用同一绑定服务；自动重试仅填空绑定并比较版本，人工查询允许不同歌手或版本。候选结果不持久化、不参与云同步；原始歌曲资料不作为全局 Track 覆盖写回。

## 多选自动匹配

歌单多选中的「自动匹配」同时提交歌曲信息与歌词，大屏先选择需要处理的歌曲。歌词候选决定歌曲身份；目录结果只有曲名、版本与歌手一致时才补充专辑和封面，不能将两个来源各自的第一名直接拼接。没有合适歌词、目录请求失败或条目受到保护时，不进行半份保存。

`batch_match_snapshot` 捕获原生账号会话和包含偏移的歌词摘要。`batch_match_commit` 在同一数据库锁及事务中比较它们，复查用户选择后原子写入两份资料。已有歌曲信息覆盖、手工选择／本地歌词及非零歌词偏移均保留；历史信息覆盖缺少可靠的手工标记，采取保守跳过而不猜测。批量任务可以停止，保留已经提交的前缀；同一歌曲去重，切账号拒绝迟到结果。绑定、BVID＋CID 和其他歌单成员不改变。

## 回归测试

`tests/song-recognition.test.mjs` 通过实际服务入口和 mock IPC 验证三个用途的长标题、实体、版本、查询次数、去重、失败与账号 ABA。原有 `lyric-query`、`automatic-lyrics`、`music-match-ranking`、`external-song-match` 和 `playlist-import` 测试保留各功能的接受与拒绝边界。执行 `npm test`、`npm run build` 和 `npm run build:large-screen`。
