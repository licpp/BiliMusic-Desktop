# 坚果云 V2 自动合并策略

五端使用相同的 Rust 同步内核。以下策略适用于首次接入 V2 和后续增量同步。

## 以高风险名单控制人工介入

低风险、可恢复字段占多数，采用自动合并；高风险名单集中在结构和身份上。

| 类别 | 字段 | 处理 |
| --- | --- | --- |
| 删除与恢复 | `__present`、`__record`、`__parent` | 有因果证据的删除与离线修改／恢复冲突时确认；正常删除传播不询问 |
| 身份与归属 | `id`、`bvid`、`cid`、`trackId`、`playlistId`、`reference`、`scope`、`folderId` | 不自动改写身份；不合法输入拒绝；归属冲突或父文件夹被删时确认 |
| 名称与描述 | `name`、`description`、`creatorNote`、标题／歌手／专辑／封面覆盖字段 | 自动处理；首次迁移无可靠先后关系时，有实际值优先，双方有值采用已存在的云端值 |
| 排序 | `displayRank`、`sortRule`、`position`、`__order` | 自动处理，稳定规则保证各端相同；新成员按集合合并 |
| 歌词 | `provider`、`providerLyricId`、`biasMs`、`manual` | 自动处理；来源与 ID 成对选择，防止混合成无效歌词来源 |
| 播放观察 | `playedAt`、`resume`、`checkpoint` | 按已有观察时间取新记录；续播取时间较新的观察，允许回退进度，不取最大秒数 |

未知字段仍由同步模型的字段许可名单拒绝，不会因为自动合并策略而接受任意新字段。

## 未设置与删除分开

首次接入 V2 的旧快照没有完整的删除因果证据。本机没有、云端有，直接导入云端记录；云端没有、本机有，直接并入本机记录。即使旧版同步基线含有该条记录，也不能仅凭缺失就认定删除。

双方独有的歌单、收藏、成员、历史等取并集，不整库覆盖。`favorite` 单独作为低风险例外：首次迁移保留单边喜欢；后续正常取消喜欢按因果关系传播；并发添加／取消采用添加优先，不要求确认。已验证的 V2 删除记录保留原有保护，避免离线旧设备自动复活已删除的内容。加入 V2 后，本机明确删除会继续作为删除操作同步。

连接并取得用户同步授权后，无冲突直接完成首次合并，不再增加第二次“确认合并”。预览入口仍保留为主动查看功能。

## 不伪造修改时间

播放观察已有时间戳，按时间选择。普通 V2 编辑按因果关系保留后一次操作；真正并发或旧版迁移缺少可靠修改时间时，用稳定规则打破平局。不会拿不同设备的操作序号当成可比较的时钟。原始候选保留在因果状态中。
