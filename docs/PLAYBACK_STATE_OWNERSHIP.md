# 播放状态所有权

桌面主窗口的 HTML Audio、Android／车机、iOS 和鸿蒙均使用同一套曲目、队列和续播规则。移动端原生服务保有实际播放状态，桌面由创建 HTML Audio 的播放流程负责。桌面托盘、系统媒体键和歌词视图订阅状态并提交控制意图。

| 路径 | UI 与前端播放协调 | Rust | 实际播放器 |
| --- | --- | --- | --- |
| 起播 | 创建逻辑播放会话，准备曲目及队列，选择用户跳转位置或续播断点。仅当前请求可以更新 UI。 | 解析曲目与音源，验证账号并访问本地缓存；负责持久化历史与断点的数据库边界。 | 打开音源并确认缓冲、播放、暂停或失败。回调携带实例和会话身份。 |
| 暂停与续播 | 发送明确的暂停或继续请求。服务退出时沿用队列及有效断点重新起播。连接诊断与实际媒体状态分开。 | 提供已保存位置及按需重新解析的音源。 | 暂停及确认恢复。按平台处理系统中断与音频焦点；显式暂停使待恢复操作失效。 |
| 后台切歌 | 根据平台能力交给自主队列，或由桌面播放器执行切换。原生回前台只采纳快照。 | 按需解析该曲的播放计划，并记录已确认的播放结果。 | 自主队列接入媒体键和自然播放结束，确定下一首及实际进度；同一事件只推进一次。 |
| 音质切换 | 保留逻辑播放会话，把新音质作为音源操作；定位和来源替换有各自有效期。 | 根据音质及缓存提供播放计划。 | 接管新音源，发布新的音源版本，沿用有效进度与暂停状态。 |

## 写入边界

- [队列状态](../src/features/player/playerStore.ts) 持有原始队列、来源和可见投影。创作者分页在一次提交里核对队列实例、预期页码和账号会话。进度采样不改变队列实例。
- [播放操作作用域](../src/features/player/operationScope.ts) 验证账号、逻辑播放和操作版本。[快照顺序](../src/features/player/snapshotOrder.ts) 负责原生驱动实例、音源版本和序号。回到同一首歌仍可能是新的播放会话。
- [媒体适配层](../src/features/player/mobileAudio.ts) 转发控制、时钟和回调。历史及断点的持久化还需检查提交时的账号会话。
- 歌词偏移按[当前歌词快照](../src/features/lyrics/biasWriter.ts)提交。曲目相同且换词后，旧选择的保存仍应被拒绝。

- 平台专有的媒体键、音频焦点与锁屏行为使用原生测试或设备验证。前端注入用例覆盖消息次序与所有权。
