# 云同步实施方案

设计日期：2026-10-28。本文为早期设计；实际实现、验证和差异见 [云同步使用说明](CLOUD_SYNC_USAGE.md)。

## 目标和界面

macOS、Windows、Android 共用 Rust 同步引擎，本地 SQLite 为主，离线使用、播放和编辑不等待同步。

设置 → 云同步，默认关闭；可选 BiliMusic 云或坚果云 WebDAV，一次只用一个提供商。关闭时不建立同步身份、不请求同步接口、不上传数据；原有 B站登录/播放联网不受影响。

启用后展示绑定账号、数据范围、上次成功时间、待同步数量，以及立即同步、暂停、设备管理、导出、断开连接。删除云端数据单独操作，不与解绑混淆。首次连接先预览双方数据数量并做本地备份，默认合并；覆盖操作放高级选项并确认影响。切换服务商不自动删旧数据，不会自动互通两个云。

## 数据范围

| 数据 | 策略 |
| --- | --- |
| 自建歌单、描述、成员和顺序 | 包含 |
| 我喜欢 | 同步收藏关系，仍为不可删除的系统歌单 |
| 用户修改的名称、歌手、专辑、封面引用 | 包含用户覆盖；平台原始信息不能覆盖用户编辑 |
| 手动歌词来源选择、时间偏移 | 包含；默认不上传第三方歌词全文 |
| 最近播放 | 独立开关，建议默认关闭，首次配置时可一起勾选 |
| 音视频文件、临时流地址、缓存、下载任务 | 不包含 |
| B站 Cookie、WebDAV 凭据、本地路径、搜索历史 | 不包含 |
| 当前播放队列/位置、音量、输出设备、主题 | 首版不跨设备覆盖 |

封面首版同步可长期使用的 HTTPS 引用，不同步 localhost 代理地址、临时签名链接。本地导入封面需后续附件能力，先提示不能跨设备恢复，不上传绝对路径。服务端不抓取任意远端 URL。

## 身份：相同B站账号进入相同资料库

现有客户端扫码后保存 Cookie，在本机调用 nav 得到 UID。这不能直接用作云认证：服务器不能相信客户端提交的 UID、昵称或截图。

BiliMusic 云首次连接需额外完成一次 B站账号验证，服务端验证 UID 后绑定内部 user_id，签发自己的短期访问令牌和每设备刷新令牌。新设备验证相同 UID 后访问同一个资料库，不另设用户名密码。刷新令牌轮换、哈希存储，支持设备撤销；退出账号立即暂停该账号同步。

实施第一步是验证身份通道：优先可获得的 B站官方服务端授权能力。当前仓库没有该能力，不承诺现有登录能直接复用为安全的云端登录。

若官方能力不可用，可评估独立的服务端扫码验证：服务器创建短期 challenge、发起二维码、轮询并向 B站核验账号，结果只能由持有该 challenge 随机交换密钥的原设备领取，显示实际账号供用户确认。必须先验证接口可用性、使用条件及风控影响，再决定上线。

备用扫码方案会让服务器短暂接触具备账号权限的 B站会话，必须明确告知；仅放隔离内存，验证后销毁，不落库、不进日志/备份/追踪，并处理进程转储。不上传客户端原有 Cookie，不把验证过程宣传成完全不接触 Cookie。若不接受该信任模式，使用已授权设备配对与恢复码；此时不能宣传仅凭相同B站登录即可在任意新设备恢复。

坚果云由其账号和应用密码授权；本机B站账号只选择独立的资料库命名空间，不能替代坚果云凭据。同B站账号还需连接同一个坚果云目录。

## 本地改造

保留歌曲键 bilibili:{bvid}:{cid}，分P独立，修改 metadata 不改身份。歌单用 UUID，收藏仍用 system:favorites。

现库没有账号隔离。新增本地访客库、每账号独立 SQLite 库，以安全生成的内部 profile_id 选择目录，不直接拼接外部输入。原库保留为本地库，经用户确认复制到当前账号，不因登录自动认领历史数据。使用有顺序的数据库迁移与备份，不继续仅靠 CREATE TABLE IF NOT EXISTS。

新增 sync_outbox、sync_record_versions、sync_conflicts、sync_state、history_events。业务修改与 outbox 同事务；远端应用不再生成出站操作。网络请求在数据库锁外。

切换账号先取消/等待旧同步任务，再切库并清理前端查询缓存。任务固定携带 profile_id、账号 generation 和提供商配置，提交前再次核对，防止旧任务写入新库。旧播放队列只作设备临时状态，不自动记入新账号历史。

## 协议和合并

不上传整个 SQLite 文件：里面有登录信息和本机路径，文件覆盖也无法合并多设备编辑。统一版本化 JSON 记录，字段包括 schema_version、op_id、entity_type/id、base_revision、device_id、device_sequence、field_patch、deleted。设备时间只展示和排序，不独自决定冲突赢家。null、空字符串、未修改分别编码。

操作 UUID 保证重复发送幂等。最近播放以事件 UUID 代替本地自增 id；一次播放会话重复更新复用该 ID，不每秒上传进度，不做实时接力播放。

| 并发场景 | 规则 |
| --- | --- |
| 两端添加不同歌曲 | 合并保留 |
| 同曲重复加入/收藏 | 按稳定键去重 |
| 一端改歌手，另一端改专辑 | 逐字段自动合并 |
| 同一字段基于旧版本被两端修改 | 保存两份，冲突界面选择，保留本地可用值 |
| 删除后旧设备回传 | 墓碑阻止旧数据复活；显式重加是新操作 |
| 删除歌单与修改并发 | 保持删除，保存可恢复的修改副本 |
| 歌单并发重排 | 首版顺序作为一个版本字段，保留冲突副本；成员增删仍合并 |
| 最近播放 | 按事件 ID 合并去重，不触发其它设备播放 |

清空历史使用已观察事件/各设备序列水位，不误删尚未同步的新事件。关闭历史同步只暂停收发，云端删除另设操作。

墓碑至少保留90天并结合设备同步水位回收；超期离线设备强制全量重基，旧 outbox 放待确认区，不直接重放。删除整个云端库递增 vault_epoch 并撤销旧写权限，防止其它设备再次灌回。

## BiliMusic 云适配

api.bilimusic.cn，独立容器与 PostgreSQL schema/受限角色，隔离官网反馈；复用现有主机和数据库，不额外要求 Redis/对象存储。

接口建议：

- /v1/auth/challenges、/exchange、/refresh：身份验证与令牌。
- GET /v1/sync/bootstrap、GET /v1/sync/changes?cursor=...：全量及增量读取。
- POST /v1/sync/commit：幂等批次、base_revision 校验。
- /v1/devices：设备列表和撤销。
- /v1/export、DELETE /v1/vault：导出与删除。

逐用户服务端递增序列形成不透明 cursor。权限、版本、变更写入同事务；提交成功才确认本地 outbox。冲突409，未知协议版本拒绝覆盖，cursor/epoch 过期要求重基；本地原子应用后才推进读取游标。user_id 一律来自已验证令牌，不信请求参数。

限制账号/设备/IP 请求频率、批次大小、文本长度和记录数；可从每账号20MB文本额度起步，根据实际服务器余量调整。日志脱敏、备份加密并验证恢复。明确数据及备份保留/删除周期。HTTPS 与磁盘保护不能宣传成端到端加密。

## 坚果云适配

Rust 直接连接 HTTPS WebDAV，数据不经过 BiliMusic 服务器。填写地址、账号、应用密码、专用目录，先测试读写与条件更新。凭据保存在 macOS Keychain、Windows Credential Manager、Android Keystore 保护的本地存储，不明文放设置或同步包。

目录示例 BiliMusic/v1/<随机库ID>/，manifest.json 指向 objects/ 中的不可变快照。先上传完整快照，再用 ETag/If-Match 条件更新 manifest，首次创建用 If-None-Match:*。失败重新拉取合并，限制重试次数；不支持可靠条件更新就禁用自动多设备写入，降级显式单向备份恢复。标准不等于具体提供商实现，需真实验证。

首版压缩 JSON 快照适合小型文本资料库，限制大小、定期压缩，不每个点击生成永久文件。WebDAV 列表支持分页；保留少量历史版本，旧对象回收有宽限期，不能删其它设备上传中的对象。

写入约10秒防抖，串行同步；前台约3分钟检查一次，启动/恢复前台补同步，历史批量上报。Android 不依赖后台 JS 定时器，不新增常驻同步服务。429按 Retry-After 等待，网络故障指数退避加抖动，401/403停止自动重试，避免不断错误认证。

## 实施阶段和必要验证

1. 身份通道可行性小样、WebDAV 条件写及分页联调，确定账号恢复方式。
2. 账号隔离、数据库迁移、版本/墓碑/outbox、纯合并函数。
3. 自有云认证及增量接口，默认关闭的设置和首次合并预览。
4. WebDAV、系统凭据存储、冲突界面和提供商切换。
5. 最近播放可选同步、撤销/导出/删除、隐私说明及三端预览包。

必要测试：并发字段/删除/重试的合并单测；越权访问、撤销、幂等、游标接口测试；两客户端离线合并、同步途中切账号、关闭后零同步请求；真实坚果云小数据联调和三端基础构建。长期真机体验交给用户反馈，不重建庞大的人工测试流程。
