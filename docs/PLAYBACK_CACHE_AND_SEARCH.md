# 播放缓存与搜索联想

播放缓存默认开启，上限 512 MB。设置中可以修改上限、关闭缓存、清理缓存。音频按播放器请求的字节范围保存为 256 KB 完整片段，不会启动整首或整个长视频的后台下载。HTTP 响应保留播放器请求的完整范围，通过流式背压按需补充 256 KB 片段；不截短 Range，避免 Apple 播放器拒绝音源。HTML 播放器只预加载 metadata；原生播放器沿用自己的缓冲策略。

重复播放优先使用缓存，不先请求播放地址。缓存索引、文件和容量设置均保存在本设备，重启后仍可使用。没有缓存的片段联网补充；离线只能播放缓存覆盖的部分，缓存不能代替完整下载。用户下载的文件优先级更高，清理缓存不影响下载、歌单和云同步。

缓存按曲目、请求音质、音频表示隔离，签名 URL 只留在内存。CDN 域名或签名变化可复用片段，路径、编码、码率、总长度变化不能混用。写入必须是完整片段，容量按近期访问清理；同一曲目优先保留容器头和尾部索引。清理时递增 generation，阻止清理前的在途写入恢复旧数据。缓存不可写时继续在线播放。

索引：应用缓存目录下 `playback-v1/index.sqlite3`。片段：`playback-v1/<hash>/<index>.chunk`。设置：应用配置目录 `playback-cache.json`。视频仍按原有代理策略按需加载，此功能缓存音频。

搜索联想直接请求 B 站 `https://s.search.bilibili.com/main/suggest`，不经过自有服务器。输入停顿 300 ms 后请求，最多显示 8 条，短期内复用结果；输入法组合期间不请求。React Query 按关键词隔离响应，旧请求不会覆盖新输入。方向键选择、Enter 搜索、Escape 收起；空输入显示原有历史。失败静默退回普通搜索。

## 验证

- Rust 本地 HTTP 模拟源：按范围读取、并发请求合并、重复读取不访问上游、重新打开索引后离线播放、离线空洞返回失败。
- 缓存单测：容量/LRU、完整片段校验、音质与音源隔离、持久化、清理及在途写入隔离。
- B 站实际联想接口 smoke test，返回不带 HTML 的建议词。
- ego 浏览器组件检查：候选键盘选择、过期响应隔离、网络失败退回普通输入，以及移动端设置排版。浏览器内 IPC 使用测试替身，不代表原生离线播放实机体验。

运行：`cargo test --offline --manifest-path src-tauri/Cargo.toml --lib`、`npm test`、`npm run build`。联网 smoke test：`cargo test --offline --manifest-path src-tauri/Cargo.toml --lib live_search_suggestions -- --ignored`。
