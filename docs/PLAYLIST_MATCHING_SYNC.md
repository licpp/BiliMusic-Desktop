# 外部歌单的歌曲条目与换源

外部歌单导入保留两种身份：`ImportedEntry` 是歌单中的原始歌曲位置，稳定 ID 根据歌单 ID 与原始序号生成；实际音频、历史、喜欢、下载和歌词继续使用 `bilibili:BVID:CID`。换源只改变条目绑定，不修改 Track 的来源身份，也不迁移它在其他歌单或喜欢中的引用。

## 数据与命令

SQLite schema 10 增加导入条目寄存器、已拥有成员集合及扩展传输状态。原始歌曲资料属于条目，不自动写入全局 `metadata_overrides`。歌单、队列和播放页通过 `importedPresentation` 共用来源歌名、歌手和封面，Track 仍使用真实 BVID + CID。已有用户全局编辑优先。

展示快照携带 `importedEntry` 与独立的 `importedSourceMetadata`；数据库录入播放和原生队列输入先还原底层来源元信息，避免把导入专辑图写成 B 站封面。原生后台切歌重新核对标准条目绑定，已删除／改绑的上下文不能继续覆盖显示。旧队列缺少上下文时，`playlist_import_contexts` 只恢复仍在歌单中的唯一绑定；同源被多张歌单以不同条目引用时不猜测。该读取不修改 schema、同步寄存器或用户资料。

播放页「更换视频」重新读取标准条目版本，复用原换源事务。保存后只替换当前歌单条目的队列位置；暂停不自动开播，播放中换源从新视频零秒开始。账号会话和播放意图校验阻止迟到保存接管新播放；其他歌单中的同源歌曲不随之替换。

`playlist_import_entries` 返回原生账号会话、条目和寄存器摘要版本；`playlist_import_seed` 创建包含未匹配项的原始清单；`playlist_import_bind` 在同一锁和事务中验证账号会话、条目预期版本与完整 Track 身份，每批最多 100 条。前端取消不是数据库会话校验的替代。自动匹配仅填补仍为空的绑定；用户已经手选或条目更新时，旧结果不能覆盖。

每个条目使用同一个因果寄存器保存来源资料与完整绑定。合并首先遵守已观察到的因果关系；并发时删除优先，其次采用现代条目而非旧档案基线，随后手选优先于自动结果，同级按操作身份确定性选择。BVID 和 CID 不分别合并。全局时间和设备时钟不参与选源。

同一歌单保留 Track 唯一性。不同条目并发选择相同 Track 时，只投影一个成员；另一条目仍保留原始歌曲并在快照中显示为待补全，同时给出重复来源信息，可以重新匹配或手选其他视频，不静默丢行。

## 迁移

原生旧 `playlist_import_archives` 是一次性迁移输入。仅迁移明确具有 text／QQ／网易云／酷狗／酷我／咪咕来源的档案；不能仅用 `import:` 前缀推断外部歌曲，因为 B 站收藏夹复制也使用该前缀。

原始行顺序决定稳定条目 ID；相同旧行和内容产生相同基线操作，两个设备独立升级不会凭随机 ID 产生重复歌曲。已有云端标准条目优先，迁移不覆盖已经存在的条目。扩展交换先读取云端再迁移本机旧档案。

旧档案标为 saved 但本机成员已消失时，不能断言是用户删除：可能是另一设备的新版绑定先经核心成员同步到达。此时不制造会压过有效选择的删除墓碑。没有档案的设备等待云端条目，不按标题猜测未匹配歌曲；所有设备都已丢失的原始清单无法由已匹配视频重建。迁移标记和旧档案保留用于恢复，后续不再把旧档案作为第二真源。

## 同步与兼容

使用独立的 `extensions/import-entries-v1` 可选扩展，不向旧核心 Snapshot 添加新 record／字段。标记文件名为 `ext-import-entries-v1-…head`，旧核心发现器会忽略。复用现有压缩、哈希校验、账号隔离、共享 WebDAV 请求准入、目录缓存和因果寄存器。

按稳定哈希分桶、每块最多 100 条寄存器，块和清单均内容寻址。清单引用整个设备的已发布条目状态，变化时只上传改变的块和小清单；单条换源不会上传整份数百或数千首的来源清单。候选、搜索响应和封面图片不上传。自动导入按批提交，共用原同步调度，不逐首发起同步。

不确定的上传保留原始冻结字节、块引用和序号，重试先确认相同提交，再发布后续修改。接收远端寄存器不增加本地意图修订，不产生扩展上传回声。远端水位回退、分叉、缺块或摘要错误保留本机数据并报告扩展错误。

`playlist_items` 是播放成员投影，同时保留核心协议的只读兼容镜像，使旧客户端仍能读取已匹配成员，并继续同步 Track 级的明确编辑、歌词、喜欢和历史。新客户端不从核心镜像反向推导绑定；应用核心同步后会重新投影标准条目，已拥有的旧／失败候选成员不能复活。兼容镜像可能随最终绑定合批产生核心增量，不是另一份选源真源。

旧客户端不理解未匹配条目及稳定绑定，不能保证它旧式的重新匹配、移除成员能无损写回新版模型。应在各设备更新后管理导入条目。删除歌单和歌曲在新客户端生成条目墓碑，与成员删除在同一事务完成。

## 验证

仓储测试覆盖幂等播种、B 站复制边界、原顺序补齐、不污染其他列表／喜欢／全局编辑、预期版本与重复目标回滚、并发手选／自动／删除、不同条目同源可恢复、核心旧镜像防复活、旧档案到达顺序。

本机模拟 WebDAV 测试验证 822 条来源清单恢复、单条换源只重传一个数据块和一个清单、接收不回传、目录发现复用、旧核心忽略扩展、模糊上传冻结重试、并发换源最终一致，以及网络处理中账号会话 ABA 拒绝写入。测试不访问真实坚果云资料。
