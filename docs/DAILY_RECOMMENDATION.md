# 每日推荐：方案、数据与验证

「每日推荐」从外部推荐源读取每日歌曲，再走与外部歌单相同的匹配流程，在 B 站找到可播放的视频。首个推荐源是网易云音乐：用户登录后，客户端读取其每日推荐列表并逐首匹配。手机端入口位于「此刻」页「探索音乐」快捷栏，不新增手机端侧栏一级导航；大屏版在左侧导航新增「每日推荐」。

本模块是设备级功能：推荐源、登录凭据、每日列表和匹配结果都不随 B 站账号切换，也不参与云同步。

## 当前状态（2026-11-26）

桌面端使用应用内嵌的官方登录页：用户点击「在应用内登录网易云音乐」后，客户端打开 `https://music.163.com/#/login`，只允许顶层导航停留在 `https://*.163.com`，并拒绝页面发起的新窗口；轮询该窗口的 `MUSIC_U` cookie，拿到后读取账号资料、写入推荐源，然后关闭窗口并删除本次登录写入的 163.com cookie。窗口使用 incognito / 临时 WebView 配置，与 B 站登录的 cookie 存储隔离。登录页的登录框不一定落在视窗内（窗口较窄时登录卡片还会横向溢出），窗口打开后每次轮询都会尝试把视窗滚动到二维码上：页面类名带构建哈希，因此按形状（96–420 px 的正方形 canvas）或「扫码登录」标签定位，页面内嵌在同源 iframe 里时也能找到；二维码已完整可见时不滚动，用户一旦滚动、点击或输入就永久停止自动滚动，非 163.com 文档（例如取消后迟到的注入）不执行任何操作。

Android 没有第二个窗口，所以把主 WebView 本身导航到同一个官方登录页：命令轮询 `cookies_for_url` 直到出现 `MUSIC_U`，写入设备库后把主 WebView 导航回应用地址。返回会重新加载应用文档（当前播放中断），登录前的说明会明确提示；按系统返回键可以随时取消并回到应用。iOS / OHOS 的 WebView 无法保证回到应用页面，因此仍只提供扫码登录。

这一路径是实测结论，不是猜测：2026-11-26 用真实浏览器登录得到的 `MUSIC_U` / `__csrf`，从 Rust 客户端调用 `profile` 与 `daily_songs` 均成功；同一天，扫码轮询在手机确认后仍返回业务码 8821「请切换其他登录方式或升级新版本再试」。继续给扫码端点补发 `NMTID` 无效，而参考实现构造 `MUSIC_A`、`_ntes_nuid`、`WNMCID` 等设备 cookie 属于模拟官方客户端、规避风控，本模块不做。8821 限制的是扫码登录端点，不是账号或每日推荐端点，因此桌面端改走官方网页登录，移动端以扫码为默认并在 8821 时提供 Android 的网页登录后备。

官方路径仍不可用：`developer.music.163.com` 是合作/审批制的开放平台，没有自助创建应用入口；`open.163.com` 的「第三方 SDK 类服务商目录」是隐私合规披露，不是开发者接入渠道；`music.163.com/st/platform/oauth/authorize` 需要开放平台签发的 `clientId`。

因此网易云推荐源不经过开放平台，只复用官方网页登录与网页端的每日推荐接口；本分支即提交上游评审的实现与验证记录。这条路径没有公开文档与稳定性承诺，上游策略变化可能让功能失效，客户端遇到限制时停止请求并提示。

### Spotify 调研结论（2026-11-25）

网易云不可用后曾计划改用 Spotify。按当日官方文档核查，Spotify 官方 Web API 同样不满足本功能的前提：

- 没有平台每日推荐数据。Spotify 自有的 Discover Weekly、Release Radar、Daily Mix、daylist 属于「算法与 Spotify 自有编辑歌单」，自 2024-11-27 起对新应用关闭；`GET /v1/recommendations` 标记为 Deprecated，同样不对新应用开放。可用的只剩 `/me/top`、`/me/player/recently-played`、Liked Songs 与用户自有歌单，只能由客户端自行合成列表，与「平台每日推荐」不是同一语义。
- 无法面向用户分发。Development Mode 每个 Client ID 最多 5 个授权用户、要求应用所有者持有 Premium、用户需逐个加入 allowlist；Extended Quota 自 2025-05-15 起只接受组织，并要求已上线服务与 250k MAU。开源应用内置一个 Client ID 服务所有用户不可行，只能让每个用户自建应用（自带 Client ID），且该用户本人需持有 Premium。
- 中国大陆不可用。Spotify 未在中国大陆提供服务，开发者条款禁止绕过地区与 IP 限制；主要用户群无法合规使用。
- 开发者政策风险。Developer Policy 禁止「与其它服务的内容或流集成」「把录音与视觉媒体同步」「向其它服务传输数据」；本模块「Spotify 元数据 → B 站搜索 → B 站视频播放」正落在这几条的射程内。展示规则还要求 Spotify 标识、逐项回链与独立展示区，与现有列表布局冲突。

因此在拿到书面许可并解决分发问题前，Spotify 不作为上游推荐源；「走通」的前提不成立。推荐源选型需要改走无需应用审核、可在中国大陆使用的开放接口。

## 范围与取舍

- v1 只读取网易云每日推荐，不提供下载、不参与云同步；不会自动写入歌单，只有用户主动「添加为歌单」时才把当天已匹配的歌曲存成新歌单或加入已有歌单。
- 匹配复用导入的候选搜索与选择规则（见 [外部歌单匹配](EXTERNAL_PLAYLIST_MATCHING.md)），不新增第二套匹配算法。
- 每日列表保留最近 7 天的抓取结果；界面只读当前推荐源的当天窗口。
- 「最近听过的声音」直接读取现有最近播放，不单独维护推荐收听历史。

## 数据位置与隐私

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 推荐源、凭据、每日歌曲、匹配结果 | 应用数据目录 `recommendations.sqlite3` | 独立于 B 站账号数据库 |
| 当前选中的推荐源 | 前端 `localStorage` 的 `recommendation-source` | 仅本机界面偏好 |
| 最近播放 | 现有账号数据库 | 沿用原有账号隔离与同步规则 |

- 目录权限在 Unix 上收紧为 `0700`，数据库及 `-wal` / `-shm` 文件为 `0600`。
- 网易云 Cookie（`MUSIC_U`）与 CSRF 只在本地数据库保存，不写入日志、错误消息、截图或云同步。
- 桌面端登录窗口使用 incognito / 临时配置；登录成功、取消、关闭或超时后都会关闭窗口并删除本次写入的 163.com cookie，不保留浏览数据。
- 推荐数据库不启用云同步；换设备需要重新登录推荐源。
- 错误信息只包含状态码与稳定的错误代码，不携带请求 URL、Cookie 或响应正文。

网易云登录在桌面端打开官方网页，移动端使用官方扫码页；但每日推荐接口并非面向第三方客户端的公开 API。接口、风控策略和可用性可能随时变化；客户端不绕过验证码或风控（不构造设备指纹 cookie、不轮换 IP 或账号），遇到限制时停止请求并提示用户。详见 [使用声明](../DISCLAIMER.md)。

不在应用内用 iframe 嵌入网易云登录页：`MUSIC_U` 与 `NMTID` 等登录 Cookie 由上游以 `Set-Cookie` 写入且未声明 `SameSite=None`，Chromium、Android WebView 与 iOS WKWebView 都会在跨站 iframe 中丢弃这类 Cookie。2026-11-26 实测在 iframe 内调用 `/api/login/qrcode/unikey` 能拿到 `unikey`，但上游同时下发的 `NMTID` 没有进入 Cookie 存储；`/login` 页面还返回 `X-Frame-Options: sameorigin`。因此移动端继续使用应用内生成的二维码，桌面端使用独立 incognito 窗口，二者都不依赖跨站 Cookie。Android 的网页登录与 iframe 无关：它让主 WebView 直接导航到官方页面，处于第一方上下文，因此不受第三方 Cookie 限制；代价是返回时要重新加载应用。

## 日期窗口与刷新

每日推荐的「一天」以 UTC+8 的 06:00 为界：06:00 前仍属于前一天。前端用 `recommendationDay` 计算窗口，后端只接受 `YYYY-MM-DD` 形式的日期并按该日期存储。

- 进入页面且当天尚无快照时自动刷新一次；同一 `source + day + credentialToken` 不会重复自动刷新。
- 手动「刷新今日推荐」始终可用；「⋯」菜单还提供「重新匹配全部」和「推荐源设置」（添加、重命名、重新登录或移除）。
- 上游返回空列表且本地已有当天歌曲时，需要用户二次确认，避免把临时异常当成真实清空。
- 一次刷新只允许一个请求持有刷新租约（`begin_refresh`）。并发的第二次刷新返回 `recommendation_refresh_busy`，避免两次 upsert 相互删除对方刚建立的绑定。
- 刷新租约在成功、失败、取消空列表确认等所有终态释放；进程异常退出时，租约 5 分钟后自动失效。

## 写入一致性

所有写操作都带 `credential_token`，行级匹配操作还带 `entry_revision`：

- 重新登录会生成新的 `credential_token`。使用旧会话发起的刷新或绑定无法覆盖新会话写入的数据。
- 自动匹配不能覆盖手动选择（`match_mode='manual'`），过期 revision 返回 `recommendation_binding_stale`。
- 刷新保留仍然存在的歌曲及其绑定；从新列表消失的歌曲才删除。
- 推荐数据库使用 WAL、`busy_timeout` 与立即事务；绑定、失败标记、重置匹配都在单个事务内完成。

## 匹配流程

1. 读取当天待匹配歌曲（`match_state='pending'`，且 `match_retry_at` 已到）。
2. 复用导入的 `findImportCandidates` 搜索候选，使用 `chooseImportMatch` 选择结果；同一时间只处理一首，并遵守搜索与详情请求的既有节流。
3. 有合格候选时写入 `matched` 与 BVID / CID；没有候选时写入 `missing`，可播放但会明确提示未匹配数量。
4. 用户可在行菜单中「更换视频」，手动选择后写入 `manual`，自动匹配不再改写。
5. 「播放全部」只播放已匹配子集，保持上游顺序并去重；未匹配数量会出现在提示中。
6. 匹配任务在播放列表导入进行时让路，账号切换时立即中止；限流与网络错误按既有退避策略暂停并在稍后重试。

匹配结果只改变推荐条目，不修改普通歌单、喜欢、历史记录或全局歌曲主键。

## 跨天复用与「添加为歌单」

同一首外部歌曲会连续多天出现在每日推荐里。为了不在第二天重新搜索一遍 B 站，匹配成功时会把绑定写入设备库的 `recommendation_matches`（`source_id + netease_song_id` 唯一）：

- 新一天写入快照时，在同一事务内为「从未被用户改过」的行（`match_state='pending'`、`entry_revision=0`）回填已有绑定；已存在的当天绑定、手动选择，以及用户手动重置过的行都不会被覆盖。
- 缓存随推荐源级联删除；一首歌从所有保留的天数中消失后，对应缓存会在同一次刷新中清除；每个推荐源最多保留 2000 条，超出时优先清理最久没有出现在列表里的歌曲，仍在列表中的绑定不会因为匹配得早就被淘汰。
- 「重新匹配全部」会删除当天自动匹配歌曲的缓存，下一次匹配真正重新搜索，随后刷新也不会把旧绑定填回来；手动选择的歌曲保留，它们的缓存也保留，跨天仍然复用。
- 缓存只保存 B 站视频绑定，不保存网易云音频；删除推荐源会一并删除。

缓存什么时候失效取决于推荐源的列表什么时候换，而不是固定的天数。判断依据只有一条：这首歌还在不在保留的日期里。网易云的每日推荐每天换一版，所以每天都会有一批歌曲退出列表，缓存能省掉多少搜索取决于相邻两天列表的重合度；退出列表的歌曲会在 7 天保留窗口结束后才真正从缓存删除，期间重新出现仍然复用旧绑定。如果以后接入的推荐源长期返回同一批歌曲（例如固定歌单），这些绑定会持续复用，不会因为跨天而失效。日期窗口目前按网易云的 06:00 定义；接入刷新节奏不同的推荐源时，需要为它单独确定快照边界和更新说明，缓存本身不需要跟着改。

「⋯ → 添加为歌单」把当天已匹配的歌曲（与「播放全部」同一集合）保存成歌单，不会重新匹配：

- 可以新建本地歌单，也可以「与 B 站收藏夹同步」在 B 站账号下新建私密收藏夹；还可以直接加入已有歌单或收藏夹。
- 本地歌单接受任意分 P；B 站收藏夹只能收录整部单 P 视频，来自多 P 视频或重复视频的匹配会跳过并在结果里说明数量。
- 歌单封面沿用首个条目的 B 站封面，不单独维护；账号切换时会中止写入并提示。

## 错误与恢复

| 错误代码 | 含义与处理 |
| --- | --- |
| `netease_auth_required` | 登录失效，界面提示重新登录推荐源 |
| `netease_login_in_progress` | 已有登录窗口或网页登录进行中，先完成或取消当前登录 |
| `netease_login_cancelled` | 用户关闭登录窗口、按系统返回键或取消，界面回到登录说明，不显示错误 |
| `netease_login_timeout` | 5 分钟内未检测到 `MUSIC_U`，关闭窗口 / 返回应用并提示重试 |
| `netease_login_window_error` | 无法创建登录窗口（通常是 WebView 初始化失败）、Android 网易云登录页 30 秒内没有打开，或非桌面平台误用网页登录命令；移动端可改用扫码，重启应用后重试 |
| `netease_rate_limited` / `netease_risk_blocked` | 上游限流或风控，停止请求并提示稍后重试 |
| `netease_verification_required` | 上游业务码 8821。移动端扫码确认后上游返回「请切换其他登录方式或升级新版本再试」，网页端拿不到登录凭据；扫码时停止轮询并提示，Android 同时提供「改用网页登录」，刷新时把推荐源记为 `auth-required` 并跳过自动刷新 |
| `netease_login_attempt_unknown` | 移动端扫码会话已失效，重新生成二维码 |
| `netease_protocol_error` | 上游返回结构无法识别，不做部分写入 |
| `netease_account_mismatch` | 账号资料不完整，要求重新登录 |
| `recommendation_source_changed` | 推荐源或凭据已变化，刷新当前页面 |
| `recommendation_binding_stale` | 行 revision 过期，重新读取快照 |
| `recommendation_binding_conflict` | 自动匹配试图覆盖手动结果，已拒绝 |
| `recommendation_refresh_busy` | 已有刷新在进行，稍后重试 |

## 已知限制

- 网易云每日推荐接口无公开文档与稳定性承诺；接口变化或风控可能导致功能不可用。
- 桌面端登录依赖网易云网页登录页和 `MUSIC_U` cookie。网页结构、cookie 名称或登录策略变化都可能让登录失效；客户端不构造设备指纹 cookie、不轮换 IP 或账号。
- 移动端以二维码登录为主，但在本机网络实测中，手机扫码确认后上游返回 8821，登录可能不可用；遇到 8821 时停止轮询，Android 可改用主 WebView 的官方网页登录（会离开当前界面、登录后重新加载应用；iOS / OHOS 不提供该后备），不尝试绕过。
- Android 无法删除单个 Cookie，网页登录的会话会留在应用 WebView 的 Cookie 存储里；换账号需要在该页面先退出登录。
- 登录页可能拒绝 `window.open` 发起的新窗口；若某个登录方式依赖弹窗，请改用手机号、邮箱或应用内二维码。
- 真实登录无法在自动化测试中完成；自动测试覆盖导航白名单、`MUSIC_U` 提取、错误契约、协议解析、状态机与存储一致性，真实登录仍需手动验证。
- 匹配准确率取决于既有导入匹配规则，不保证每首歌都能找到正确视频；未匹配与手动更换是正常流程的一部分。
- 跨天缓存直接复用之前的 B 站绑定，不会重新校验该视频是否仍然存在；如果视频下架或失效，可在行菜单「更换视频」或「重新匹配全部」重新搜索。
- 推荐源与登录状态不参与云同步，多设备需要分别添加。
- v1 不提供下载，也不在推荐页展示歌词或评论；只有用户主动「添加为歌单」时才会写入歌单或 B 站收藏夹。

7. 安全验证（8821）：需要一个会被上游拒绝的账号或网络环境，且只在移动端二维码登录路径出现。扫码并在手机上确认后，界面应显示「网易云要求安全验证，请稍后重试或改用网页登录」、二维码被替换为错误占位符、轮询停止（不再出现新的 `[netease] stage=qr-poll` 日志）；Android 底部是「改用网页登录」，iOS / OHOS 是「重新生成」；若已登录时每日推荐返回 8821，则应出现验证专用告警，且切换日期后不会被自动刷新再次触发。

9. 大屏版：运行 `npm run dev:large-screen`（或安装大屏 APK），从左侧导航「每日推荐」进入，检查 1280×720 与 1920×1080 下的横幅、推荐源设置弹窗、方向键焦点、遥控器返回与深色 / 浅色主题；Android 车机上的触控与后台播放仍需实机验收。
