# v2 同步正确性测试

2026-11-14。本轮只运行代码测试，未构建安装包、推送源码或发布官网。

## 环境与复现

生产使用的共享 Rust 执行器连接本机 `127.0.0.1` 模拟 WebDAV，使用临时目录中的合成 SQLite 账号（UID 42）。模拟器不读取真实凭据或用户数据库，也不请求真实坚果云。网络顺序、故障点和随机种子均由测试控制；测试结束清理临时资料，失败时保留合成数据库并打印路径。

```sh
# 包含迁移、调度、协议、执行器和模拟器的完整 Rust 单元回归
node scripts/test-sync.mjs --all

# 故障矩阵、随机时序、5000 首冷恢复等专门场景
npm run test:sync

# 默认 128 个种子的长随机测试
npm run test:sync:stress

# 只重放指定场景、指定种子
node scripts/test-sync.mjs --seed 42 --filter production_library_random_offline_edits_restarts_deletes_and_readds_converge

# 前端同步生命周期、逐项冲突选择及应用其他功能回归
npm test
```

`--seeds N` 可扩展到 4096 个种子；`--seed N --seeds M` 从 N 开始运行 M 个。以上入口只生成测试程序，不构建或分发安装包。真实服务测试保留为显式 ignored，不由这些命令开启。

## 检查的性质

| 场景 | 断言 |
| --- | --- |
| 独立事件 DAG oracle | 不调用 CRDT 合并来计算预期候选；按事件观察关系判断哪些字段赋值应保留，检查随机稀疏观察、乱序、重复后的所有寄存器候选 |
| 四端资料库随机时序 | 离线新增、同字段/异字段修改、删除、重新添加、进程重启、回包丢失；恢复公平传输并处理冲突后，全部 SQL 视图与完整因果文档相同，独有新增不丢失 |
| 五端统计随机时序 | 使用实际采样入口记录整数毫秒；独立求和全部样本，对比每台设备最终总数，确认收到的统计不会作为自身贡献再次上传 |
| 资料库首次迁移的 33 个请求位置 | 每处请求执行前失败，所有写请求另测服务端已提交但客户端收到失败；重启重试后，冷设备获得原始资料且无接收回声 |
| 统计首次迁移的 23 个请求位置 | 相同故障矩阵；失败后继续记录的新样本也必须保留，重试和冷恢复不重复计数 |
| 上传中继续编辑/采样 | 冻结计划只能确认其精确前缀；后来的编辑保留，统计新样本在下一次发布前仍在 outbox |
| 提交边界并发写入 | 网络校验后、业务投影事务前修改本机资料；本轮拒绝覆盖，下轮与远端独立修改合并 |
| SQLite 事务故障 | outbox 插入、序号更新、发布代保存、运行态写入、确认删除、业务投影失败；外部已预留水位不能被复用，待发意图不丢 |
| 统计投影事务失败 | 多来源汇总不能部分入库；失败后的新样本及重试仍得到准确总数 |
| 交替因果依赖 | A1 → B1 → A2 → B2 → A3 的尾日志可交错接收；必要来源暂不可见时保留 SQL，不错误跳过依赖 |
| 部分可见、迟到旧 PUT、损坏下载 | 不回退已确认水位，不把读不到的对象当空库，不落库半个资料库；网络恢复后继续收敛 |
| 伪造水位及同代分叉 | 有效哈希也不能绕过 head/manifest 水位核对或同代分叉检测 |
| 检查点与控制记录清理 | 超过 64 个尾包、90 次在线更新后，长期离线设备的独立修改及冲突候选仍可恢复 |
| 5000 首规模 | 首次迁移与全新设备冷恢复完整；之后只改一个歌单字段，新增压缩数据对象约 360 字节（测试上限 8 KiB），不回传整库 |
| 压缩体积上限 | 超过 32 MiB 的解压内容拒绝解码，避免仅按压缩大小放行 |
| 最近记录与跨域引用 | 201 首挤出本机 top-200 时，另一台离线重播的记录仍保留；一端取消收藏、另一端新增播放记录不会丢失歌曲引用 |
| 未见候选的同值编辑 | 预览收到未显示的版本后，本机恰好改成相同值；与云端后继仍形成真实冲突，不能静默丢失本机编辑 |

现有单元用例另覆盖旧设备一次性合并、缺失/null、UP 备注清空与顺序、父子引用恢复、账号/目标隔离、恢复备份与复制数据库、更换统计来源、播放记录选项、统计月末跨天、限流和调度阻塞。

## 本轮发现并修复的问题

1. **删除一侧缺少恢复候选。** 只有字段编辑与删除并发时，存在性寄存器可能仅剩 false。现在冲突菜单同时允许保留与删除，删除发起端也能恢复远端离线修改。
2. **交替修改导致冷恢复停滞。** 旧接收器要求一次处理完整个设备的尾日志，可能丢弃本轮已验证前缀，使两端交替依赖永远无法前进。现在先验证所有包，再合并检查点并按依赖交错应用增量；全部完成才更新 SQL 和接收水位。
3. **校验与投影之间存在本机编辑窗口。** 投影前、冲突决策入队前在同一数据库事务中重核本机视图；发生新编辑时保留修改并重试，避免旧投影覆盖新操作。
4. **未显示的相同值抑制真实编辑。** 本机实际改动即使等于已收到但未显示的候选，也必须分配自己的操作身份；不能因此误判无变化，随后被另一个未见后继覆盖。随机 oracle 增加了非空编辑必须产生事件的断言。
5. **最近记录裁剪与跨域引用误删。** 本机最近 200 首之外的缺席不产生全局删除；本机取消最后一个引用，也不删除另一端或进度域仍可能需要的歌曲事实。未引用事实只从可见快照隐藏，明确的歌词重置仍正常同步。
6. **提交声明缺少交叉核对。** 检查域水位不能倒退或丢失，manifest 的覆盖范围必须与 head 声明一致。

## 验收边界

随机测试和故障注入验证的是具体实现及所覆盖状态，不构成对所有历史的形式化证明。最终一致性的前提是：设备完成升级和一次性合并，网络最终恢复、必要对象可读取，真实内容冲突已处理，并且每个设备最终有机会同步。旧版与新版的暂时分轨符合既定迁移方案。

本轮未消耗真实坚果云额度。真实服务的限流、各平台系统 HTTP 和生命周期合同仍需后续验收；不会据此自动发布。

## 本轮结果

- 完整 Rust 单元回归：180 通过，0 失败，19 项因需要外部环境等条件按原设置跳过。
- 前端回归：205 通过，0 失败。
- 修复后的扩大随机测试：4 设备资料库、5 设备统计各 128 个种子全部通过，共 8,192 步资料库操作和 11,520 次统计采样；另有 128 个种子的独立事件 DAG 核对。完整回归中还运行了默认 256 种子的 DAG 核对。
- 5,000 首歌曲冷恢复通过；单字段修改新增压缩数据对象为 361 字节（具体压缩结果随合成身份略有变化）。
- 资料库/统计故障矩阵分别覆盖 33/23 个请求位置，并对写请求额外验证“服务端已完成、客户端得到失败”的情况。
- `node --check`、所改 Rust 文件格式检查及 `git diff --check` 通过。
