# 云同步使用与实现状态

更新：2026-10-28。

## 使用

在设置中登录B站账号后选择云同步服务商。默认关闭。配置凭据、勾选范围与授权说明，点击“连接并预览合并”，确认预览后才首次上传。以后本机修改约10秒防抖，前台约3分钟检查远端，恢复前台补同步；Android不增加常驻同步服务。

两端使用同一个B站账号和同一个服务商。坚果云还需使用同一坚果云账号和目录；两个服务商不自动互通。坚果云使用应用专用密码，不使用登录密码，凭据不经过我们的服务器。

首次启用账号隔离时，原资料保留在本机访客库。可点击“导入本机原有资料”合并到当前账号；不会因登录就自动把整机历史归给当前账号。首次同步有一份本地同步数据备份；主动备份只保存个人列表与修改，不包含登录凭据。

## 存储控制

- 自有云只保留当前快照，单账号上限3MB、500个歌单、5000首歌曲、10000条歌单成员；当前部署最多200个云资料库。
- 最近播放是可选项，最多200首；“我喜欢”复用收藏关系。
- 只有仍被同步歌单、收藏或已选择同步的最近播放引用的歌曲，才上传其标识和用户修改字段。取消所有引用后，编辑内容与歌词设置随合并清理。
- B站原始标题、UP主、封面、时长、分P页码等在设备上获取和缓存。云端不缓存这些资料，不保存媒体地址或音视频文件。
- 歌词只同步来源/ID与偏移。新设备按已选ID获取歌词正文；本地导入歌词需在新设备重新导入，偏移仍可保留。
- 用户自定义封面只同步可访问的HTTPS引用，不上传本地文件或临时代理地址。
- 无法从B站加载的条目保留在列表中，可稍后重试或编辑，不会自动删除用户收藏。

## 两种同步实现

自有云：同域独立API `https://bilimusic.cn/api/sync/v1`，独立容器、数据库与受限角色。服务端验证B站会话后绑定UID，签发每设备随机令牌，有效期30天，摘要入库，最多10个有效设备会话；不保存B站会话。首次连接的授权说明明确披露此一次性验证，不声称是B站官方OAuth。

以SQLite状态与上次同步基准进行逐记录、逐字段三方合并；本地业务数据和同步基准在一个事务提交。离线编辑留在SQLite，下次比较，无需逐秒上报或复制整个数据库。同步中编辑会再次重基，切换账号中断上传并校验账号范围。

坚果云真实联调发现本次服务对条件PUT和重复MKCOL没有提供期望的互斥保证，因此不使用共享文件覆盖或锁目录。目录为 `BiliMusic-sync-v1/<B站UID>/<设备UUID>.json`，每设备只写自己的文件。通过带因果版本的字段寄存器合并，支持并发修改不同字段、显示同字段冲突、删除不被旧副本复活。删除正文压缩为小型标记，已读取的新状态会写回设备文件，避免长期保留旧编辑内容。每设备快照最多12MB，每资料库最多10个设备文件；请求有防抖和退避。

停用设备的文件只有用户确认不再使用后才能在坚果云专用目录移除；删除最后包含某项未传播删除的副本可能改变恢复行为，不自动移除活跃设备文件。

## 安全和删除

凭据存储：macOS Keychain、Windows Credential Manager、Android Keystore加密存储。普通设置、同步包和运行日志均不包含凭据。

断开连接保留远端资料；自有云会尝试撤销本设备令牌，网络失败明确提示。删除云端资料删除快照并撤销所有设备令牌，本机资料保留。备份加密、每天轮换，只保留两个日版本；它不是端到端加密服务。隐私说明在客户端和官网同步更新。
