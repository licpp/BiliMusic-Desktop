**BiliMusic 架构整理与缺陷修复方案**

设计日期：2026-11-15。依据：当前 0.3.4 工作区，包含尚未发布的修改。本文件是实施方案；不表示以下修复已经完成。

目标是修复已确认的问题，减少各端业务分叉，让后续功能修改能在共享层完成。保留现有产品风格、歌曲标识、云端 V2 格式和用户设置；采用逐批替换的方式，不同时重写播放器、数据库和同步引擎。

**1. 审查基线与实施边界**

当前基线：前端测试 345 项通过；Rust 测试在现有 Tauri 配置绕过方式下 226 项通过、22 项忽略；TypeScript 与 rustfmt 检查通过。Mac 默认 Rust 测试入口存在配置错误，需优先修复。审查尚未进行真机验证。

| 编号 | 发现 | 修改目标 |
| --- | --- | --- |
| A01 | 旧播放控制失败可覆盖新歌曲状态 | 播放会话与操作版本校验，过期结果不再提交或回滚 |
| A02 | 歌词正文恢复可覆盖更新后的人工选择 | 独立正文补全命令，数据库条件更新 |
| A03 | 切账号后旧编辑请求可重新打开编辑框 | 前端请求守卫、原生账号会话校验 |
| A04 | 大屏合集未展开时，续播可能落到第一集 | 共享合集定位和分 P 解析用例 |
| A05 | 暂停后点击当前歌曲或播放全部可能不恢复 | 区分主动播放与仅更新队列 |
| A06 | 标题清洗误删《听海》等正常歌名的首字 | 按上下文提取歌名，保留原始候选 |
| A07 | 鸿蒙重复定时只重设时间，未恢复播放 | 对齐定时到期后重复操作的语义 |
| A08 | 合集展开分 P 时丢失已有播放量 | 元数据纯转换与字段保真测试 |
| A09 | 本地整理依赖全库同步导出成功 | 按实体直接校验，解除同步层依赖 |
| A10 | Mac 默认 Rust 测试入口失败 | 测试入口和 Tauri 配置统一 |
| R01 | 鸿蒙后台队列推进依赖 WebView | 验证并补齐原生自主推进能力 |

A01—A08、A10 已有代码或模拟复现。A09 是条件性缺陷，触发条件是其他同步资料非法或超出导出限制。R01 可以确认能力缺口，但不能据此声称已复现所有真机后台故障。A03 当前确认的是旧界面回写，尚未确认跨账号数据库损坏。

不改变以下业务约定：单个视频总时长决定断点续播，阈值保持 0—60 分钟且 0 表示全部；合集进度和分 P 续播独立；歌曲 ID 继续使用现有 BV/cid 标识；手动编辑的标题、歌手与歌词选择仍受保护；现有 V2 因果合并、outbox、首次旧资料导入与跨端最终一致性保持。

**2. 第一批：先建立可以依赖的测试入口**

将审查中的复现脚本转成正式回归测试，保留真实业务模块，只替换网络、IPC、时钟和系统播放器边界。旧结果必须能让新测试失败，修复后再通过。

统一 Rust 测试入口，处理 macOS 私有 API feature 与 Tauri 配置校验的不一致。测试使用明确的测试配置，打包继续使用生产配置；不为测试关闭生产能力。同步测试脚本和 CI 调用同一个入口，开发者无需手工设置临时环境变量。检查 22 个忽略项的原因，区分设备依赖与可以自动运行的测试。

建立三组固定数据：旧版本数据库、视频/分 P 元数据、播放器命令序列。预览和审查产物继续放在被忽略的 artifacts 目录，不把账号资料或测试入口放入产品页面。

本批验收：本机直接执行约定测试命令成功；普通前端和大屏前端均能构建；现有测试数量和忽略原因可追踪。

**3. 第二批：统一异步操作的有效期，修复 A01/A02/A03/A05**

需要分别识别三个生命周期，不能用一个全局计数器代替所有语义。

| 身份 | 何时改变 | 作用 |
| --- | --- | --- |
| 账号会话 | 数据库账号每次成功切换，包括 A→B→A | 防止旧账号任务执行或回写到当前账号 |
| 逻辑播放会话 | 选曲、明确重播、原生自然切歌或单曲循环新一轮 | 区分同一首歌曲的不同播放实例 |
| 单类操作版本 | 暂停/恢复、seek、音量、速度、换源各自出现新意图 | 防止同会话内旧操作撤销后续操作 |

进度采样、封面修正、歌词刷新不更换播放会话。队列排序只改变队列任务的版本，不使暂停、调速等有效控制失效。无缝音质切换和透明网络恢复保留逻辑播放会话，递增音源版本。

前端操作令牌由账号 epoch、逻辑 sessionId、操作类别和该类别版本组成。每个 await 后的成功提交、错误提示和回滚都检查令牌；回滚优先采用当前原生权威快照，不能直接写回请求开始时捕获的旧状态。

先在 playerStore 保持公开 API，增加小范围 helper；统一 seek、volume、rate、transport 的错误路径。后续再让原生快照提供 sessionId，覆盖原生自主切歌和同曲循环。现有原生 revision 同时承担换源等职责，不直接拿它充当逻辑播放会话。

主动播放使用幂等的 ensurePlaying：当前曲暂停则恢复；正在播放则保留位置；正在解析则合并意图；出错才重新加载。仅更新队列使用独立 adoptQueue 语义，不擅自恢复暂停。明确 startAt，包括 0，继续生效。播放行操作不通过 toggle 表达“确保播放”。

账号界面操作保留现有 accountEpoch，并补请求序号和组件存活校验。编辑器、成功提示和缓存失效均遵守同一有效期。原生侧在当前数据库会话中维护随机进程身份与单调 generation，前端写请求携带原生签发的 opaque accountSession。取得数据库锁后再检查身份并写入，切账号操作使用相同的锁与锁顺序，避免检查与实际执行之间再次切换。

先覆盖歌曲保存、元数据修改、歌词选择/补全、喜欢/删除、加入歌单和批量导入等写操作。多步操作每一步携带同一账号会话，不能中途改用“当前账号”。账号失效返回专用取消结果，不显示为网络故障。现有同步账号门禁、事务和播放进度保护继续复用。

必测场景：A 恢复等待→播放 B→A 失败；A→B→A；恢复→暂停的逆序返回；调速 1→1.5→1；换源期间暂停；队列修改期间仍能完成有效控制；切账号或等待数据库锁时切账号；延迟保存完成后旧编辑器不再打开。

**4. 歌词正文补全：数据库保证不覆盖新选择**

改动入口是 services/desktopApi.ts、Rust 歌词命令、lyrics repository 与同步歌词投影。保留现有下载和 TS 歌词解析，不另写一套 Rust LRC/逐字解析器。

新的调用顺序是：lyrics_get 同锁读取当前选择及 guard → 使用现有 lyrics_restore_selected 下载 → 使用现有 candidateLines 解析 → lyrics_complete_selected 条件补全。

guard 包含 provider、providerLyricId、本地 writeToken 和 accountSession。新命令只更新 raw_text/parsed_json，SQL 条件同时要求 trackId、provider、歌词 ID、writeToken 一致且正文仍为空。它不修改歌词版本、人工选择标记、偏移量，也不复用代表“选择歌词”的 lyrics_save。

需增加一次本地 V6 数据库迁移：lyrics 新增 write_token，旧行补随机 token。新增行、歌词选择/正文/解析结果/人工选择状态实际变化时更换 token；只改 bias_ms 不更换。初期使用限定业务列的小范围 SQLite trigger 覆盖 repository 和同步直接 SQL 写入，token 本身的变动不递归触发。删除重建获得新 token，可拦截相同歌词 ID 的旧请求。

正文补全过期返回 stale，保留当前选择；账号不符不返回另一个账号的歌词。并发相同恢复可合并，失败不删除选择、不无限重试。writeToken 和 accountSession 不进入云端快照，正文缓存补全不产生同步业务增量。

必测场景：恢复 A 期间选 B；A→B→A；删除重建；同 ID 人工改正文；仅调整偏移仍能补全且保留偏移；两次补全乱序；账号 A→B→A；数据库迁移首次、重复和中途失败。另验证补全前后 V2 业务投影不变。

这次存在本地 schema 升级。回退构建也需识别 V6；可以停用新补全入口，不能直接装仅识别 V5 的旧二进制，也不能通过降版本号或覆盖数据库实现回退。迁移前使用现有备份能力留存备份，迁移事务失败应完整回滚。

**5. 第三批：列表播放、合集续播和元数据共享**

新增 features/player/listPlayback.ts，先提供纯 planListPlayback，再提供只处理异步分 P 解析的 prepareListPlayback。输入是排序后的条目、可见集合、播放来源，以及“指定歌曲／播放可见结果／继续 checkpoint”的选择；输出是 ready、需要解析或不可用。最终仍由现有 playFromList 提交，不再造播放器和持久化逻辑。

继续合集时，从完整集合先按 BV 定位，再解析实际 cid，最后使用原 checkpoint 的位置。找不到记录不能把旧进度应用到第一集。临时搜索不影响继续上次的定位；“播放搜索结果”则只使用可见集合。异步解析完成前检查账号与最新播放意图。

先迁移普通合集，确认行为等价，再迁移大屏合集修复 A04，随后接入普通歌单、大屏歌单和分 P 列表。保留普通/移动/大屏的视图、遥控焦点和导航差异，共享业务函数。

新增 domain/videoMetadata.ts 的纯转换，逐步承接 mediaSources、collectionTrack 和相关来源转换。明确视频级 title、发布日期、播放量、UP 信息、封面、partCount，与分 P 的 cid、名称、时长、章节上下文。继续输出现有平铺 Track，不迁移歌曲主键或同步结构。

已知播放量 0 与未知值分开；detail→Track→detail 不丢已有字段；来源标题与用户编辑标题分开；未知字段不猜造。TS 与 Rust 使用同一组边界 JSON fixture，检查前台、原生后台播放、队列、歌单和听歌统计的显示契约。普通多 P 使用分 P 标题、普通单 P 使用 BV 标题；独立合集章节沿用已确定的章节规则。

必测场景：未展开非首 P 续播、已删除 cid、混合多 P 与独立 BV、展开预算导致占位、全部排序规则、过滤后播放、解析时切账号/切歌；播放量缺失/0/正常值、旧 Track、人工元数据、标题与发布日期往返转换。

A06 同批独立修复：只在明确的节目语境中清洗“在……听……”前缀；书名号或引号内的歌名优先保留，原始完整标题保留为候选。覆盖《听海》《听妈妈的话》《听说爱情回来过》及本轮新增的录音棚/私藏馆标题。保持候选数和请求预算有界，不靠扩大搜索次数掩盖解析问题。

**6. 本地整理与同步职责分开，修复 A09**

list_preferences::save 不再调用 sync::storage::export。把实体 ID 解析成明确枚举，在事务中执行参数化 EXISTS 查询，确认目标属于当前账号；整批任一项非法则全部回滚。

固定视图可直接设置；歌单、关联收藏夹、文件夹和收藏合集按各自表校验。保留“未收藏合集也可设置浏览排序”的合法能力，但不能为不存在的收藏排列写 rank。不再从同步配置、第一条收藏夹或默认 UID 推测账号。

现有 local-sort:<entity> 键先保留，由小型 LocalListPreferences 模块封装。按播放量排序继续只在本地覆盖，旧同步允许的规则值不扩展，避免其他旧客户端拒绝同步。云端 apply 保留本地覆盖；未知本地值忽略但保留，不在这次清理中删除。

把实体 ID、rank 和规则校验移到 Rust domain 模块，供 interface、repository、sync 使用，解除 sync::model 对 interface 的反向依赖。

验收：没有配置同步、无关资料非法或全库超限时，合法列表仍能整理；已删除或其他账号实体被拒绝；批量写入原子性；同步不上传播放量本地排序；耗时主要随本次修改数量增长。

**7. 第四批：播放器平台合约与鸿蒙后台能力**

统一 nativeAudio、iosAudio 中重复的播放状态定义，新增平台中立 contracts。PlayerSnapshot 明确 engineInstanceId、sessionId、sourceRevision、sequence、状态、位置、时长与必要定时状态；ControlCommand 使用 pause/resume/seek/setRate/setVolume 等明确类型。悬浮歌词外观设置不再混入每一条进度快照。

engineInstanceId 处理服务或驱动重建；sessionId 表示逻辑播放；sourceRevision 表示同会话换源；sequence 只处理事件顺序。先新增可选 IPC 字段、适配旧事件，再逐端输出完整字段；最终内部状态必须正规化。保留 iOS 重新绑定、Android service 生命周期和鸿蒙 AVSession 的必要差异。

只为确有差异的能力提供 capabilities，例如 autonomousQueue、seamlessSourceSwitch、nativeSleepTimer、snapshotRebind。队列、定时、悬浮歌词是独立能力，不把所有系统服务塞入一个接口。

A07 可先独立补齐：鸿蒙定时已到期、当前曲有效且原时长有效时，重复操作重新计时并幂等恢复；失败不伪造 playing。命令序列与 iOS/Android 对照。

R01 单独实施：先验证现有鸿蒙桥接能在 WebView 不执行 JS 时完成 ArkTS→Rust→ArkTS 的请求与响应，再接队列镜像、模式和上下文，复用 native_playback::resolve，不复制 B 站解析、续播和统计实现。桥接若仍必须经前端转发，就不满足自主后台播放的目标。

解析请求携带 requestId、账号会话和逻辑播放会话；停止、切歌、切账号、定时到期后的迟到响应一律不启动旧请求。避免在串行命令队列中等待只能由同队列回调完成的 Promise。切歌阶段保持系统允许的后台任务连续性，具体 API 行为通过模拟器日志及真机确认。

同一时刻只允许一个队列推进者。原生确认队列版本并报告 autonomousQueue 后，前端才让出控制；前端恢复后读取快照，不再根据 ended 重复切歌或重复记录统计。能力回退同时撤销原生 pending 请求并明确交还所有权。

必测场景：完全停用 JS 消费者后 A→B→C、单曲循环、随机和队尾停止；重复/乱序/超时解析；切账号和 stop；解析期间队列删除/修改；定时到期；前台恢复；驱动重建后 sequence 重新开始。模拟器无法覆盖的系统后台限制单列，不以 mock 通过代替真机结论。

**8. 第五批：拆依赖与同步兼容边界**

前端保持“视图调用用例，用例组合纯规则与服务，服务访问 IPC”的方向。API 类型从 desktopApi.ts 逐步移到领域模块，旧文件短期保留转导出，调用方分批迁移；已迁移的旧实现立即删除，避免长期双写和双逻辑。无需依赖注入框架或新的全局事件总线。

先解除两组已由运行时依赖图证实的循环：

- LibraryView/TrackActions/DownloadsView：拆出 MetadataDialog、PlaylistPicker、TrackMenuButton；页面不再充当共享组件出口。
- MobilePartsPage/CollectionsView/SeasonBrowser：拆出 CollectionBookmark 与 CollectionDetail；嵌套导航由轻量容器/回调装配，详情不反向引入外层页面。

验收使用实际运行时 import graph，type-only 引用不为消除图形环而硬拆。按钮的独立导入不再拉入整个编辑器或下载页面。

账号相关 QueryKey 统一工厂，私有资料携带账号会话作用域；公开且与账号无关的视频资料继续共享缓存。缓存取消、失效和 account-changing 事件集中处理，保留少量明确事件，不添加万能总线。

同步保持现有执行阶段、outbox、因果合并与投影事务。将 V1 解码和一次性导入集中到 legacy_import，保留唯一入口；已进入 V2 的设备不重新读取 V1。未使用的 BiliMusic 云传输隔离到独立模块或默认关闭 feature，保留旧配置识别，不静默清除配置或凭据。

同步引擎逐步接收明确的 repository、账号和传输上下文，Tauri 命令只负责参数和结果转换。先移动定义与包装，再调整内部结构，不能在移动文件时改变 wire 校验和合并规则。

同步回归覆盖：首次 V1→V2、空新账号、旧本地资料合并、重复重试、上传成功但响应丢失、多端乱序/离线重连、删除与修改冲突、账号及 WebDAV 目标隔离。重构前后最终业务快照应相同；未修改资料不增加网络操作和上传字节。

全量 capture/apply 的增量化、N+1 批量化和墓碑回收另行评估。先测本地耗时、SQL 次数、数据库增长和云端字节；墓碑回收必须证明长期离线设备重新加入不会复活删除项，不能作为删除旧代码的附带修改。

**9. 第六批：归并样式与完善跨端验证**

按组件收拢最终生效样式，不借机改变用户已经验收的界面。先处理 list-sorting.css 同选择器覆盖和重复 sheet 规则，再逐组迁出 editor-polish 中的编辑器、列表工具栏、同步提示和 Android 下载目录样式。

每批只移动一组规则，保留导入顺序并对比截图。最终形成主题 token→组件→布局版本→必要平台差异的关系；全部层级明确后再决定是否采用 @layer，不能直接套 layer 导致旧的未分层规则反过来覆盖组件。
